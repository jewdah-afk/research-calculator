## How to research Birb (the tools are in `tools/`)
1. Download Birb's bundles **outside the repo**: `playtest/tools/fetch_birb.sh /tmp/birb`. This creates the `*.pretty.js` files.
   - The main logic is in `game-*.js`.
   - The data tables are in `maps-*.js`, `editors-*.js` and `main-*.js`.
2. Find a function and everything it calls:
   `SKIP=Ii,_U,DU,uo,mI,Bi,ZE,Gh,ap,IU,Vh,Ga,hp,lp NODE_PATH=... node playtest/tools/deps.js /tmp/birb game-XXXX.js name,m:methodName 2`
   - `m:` looks up a class method.
   - Quote names that contain `$`.
3. Ask the live game directly:
   - Start `node playtest/tools/birbrepl.js`. It opens birbplay.com headless and serves port 9333.
   - Then run `echo 'return game.expeditionManager.getCommonSacrificeMilestoneLevel()' | playtest/tools/q.sh`.
   - Internal exports load with `await import("/assets/main-XXXX.js")`.
4. Add a probe for each new formula on **both** sides in `parity/parity.js`:
   - the Birb side uses `window.game` / `g.expeditionManager`;
   - the playtest side uses `PT.EXP`.
   - Add save states to `parity/scenarios.js` and run parity.
   - Probes must return numbers or booleans; a string becomes NaN.

Gotchas we hit:
- **Birb drops bad save data on load.** Inventory items without an `instanceId`, unknown item names, a 3rd copy of an equipped artifact and equips over the slot count are all dropped, so scenarios must be valid.
- **Birb reads mine area as `journeyVersion: 1 ? highestArea : max(collapseLevel, milestoneLevel)`.** Mine scenarios need `journeyVersion: 1`.
- **`em.parrotBonuses` goes stale in probes.** Call `em.refreshParrotBonuses(g.getEquippedArtifactNames(), g.getEquipmentMultipliers(), g.getEquippedArtifactInfusionLevels())` first.
- **Escape `$` in shell arguments.**
