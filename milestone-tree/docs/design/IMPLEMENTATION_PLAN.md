### 1.1 Parity-safe rules for `port/rbx/view.js` (and `session.js`)

The JS game and the Luau port must produce byte-identical JSON (`./test.sh view`, `view_cmp.py` compares values and
key order exactly).

1. **ES5 only.** No `let`/`const`, arrows, template strings, `for..of`, spread, default parameters or classes. Use
   the file's existing style.
2. **Fixed key order.** Build each object literal in one expression, in the key order given in this section. When a
   key is added later (`n.cn = …`), it goes after all literal keys, at the same place on every path.
3. **`null`, never `undefined`.** JSON drops `undefined`, so one side would lose the key. Every optional field is set
   to a value or to `null`.
4. **Forced booleans.** Write `x ? true : false`. A Decimal, a string or a Luau value must never leak truthiness.
5. **No Decimal in the view.** Numbers the player reads go through `format` / `formatWhole` / `formatTime`. Numbers
   the client computes with are plain JS numbers: integers where possible, and per-mille for progress (P8).
6. **Display-only functions** (`rbx_displayOnly` in session.js) are read through `rbx_v(t, L, key)`, never from `tmp`
   directly.
7. **Every builder that can throw** runs inside `try { } catch (e) { … rbx_err(what, e) }`, so one bad field never
   blanks the screen. The map and HUD builders are wrapped separately.
8. **NaN guard.** `rbx_nn(s)` returns `null` when the formatted string contains `"NaN"` (D§15). Use it on every
   `ef`, `eff`, `cur` and `rw`.
9. **Theme colours** come from `colors[options.theme] || colors["default"]`, never from `colors_theme` (undefined in
   the port).
10. **After every edit:** `node port/build.js` (regenerates `src/server/Game/rbx_view.luau` and `rbx_session.luau`),
    then `./test.sh view`.
11. **No `Date.now()`** in view code, except where the game already calls it (pm's flickering resource).

Helpers to add at the top of view.js:

```js
// null when a formatted value is NaN (the game shows "NaN"; the client hides the line instead)
function rbx_nn(s) { s = rbx_str(s); return s.indexOf("NaN") >= 0 ? null : s }
// progress toward `need`, per mille, floored, on a log scale. 1000 only when have >= need. null when unknown.
function rbx_pr(have, need) {
	if (have === undefined || have === null || need === undefined || need === null) return null
	have = new Decimal(have); need = new Decimal(need)
	if (have.gte(need)) return 1000
	if (have.lte(1) || need.lte(1)) return 0
	var a = have.log10(), b = need.log10()
	var r = a.div(b).toNumber()
	if (r < 0.01 && a.gt(1) && b.gt(1)) r = a.log10().div(b.log10()).toNumber()   // tower numbers
	if (!(r >= 0)) return 0
	return Math.min(999, Math.floor(r * 1000))
}
// the label of a layer's first hotkey ("P", "Shift+M", "Ctrl+E", "C+M"): the text before ":" in its description
function rbx_hk(l) {
	var h = layers[l].hotkeys
	if (!h || !h.length || !tmp[l].hotkeys || !tmp[l].hotkeys[0] || !tmp[l].hotkeys[0].unlocked) return null
	var d = rbx_str(h[0].description), i = d.indexOf(":")
	return i > 0 ? d.substring(0, i) : null
}
```

### 1.4 Structured fields on tab components

Every field is **appended after** the node's existing keys, so the old client keeps working in wave 1. `h` always
stays, as the fallback.

**All components** (`rbx_component`, after the `cst` line): `n.cn = rbx_str(name)` and `n.ci = <index>`.

* `cn` is the tabFormat component name: `main-display`, `prestige-button`, `resource-display`, `upgrades`,
  `buyables`, `milestones`, `challenges`, `achievements`, `clickables`, `grid`, `display-text`, `raw-html`, `row`,
  `column`, `blank`, `h-line`, `v-line`, `bar`, `microtabs`, `rbx-burn`, …
* `ci` is the 1-based index of the entry in the array it came from, counted **before** null entries are dropped.
  For the default layout (no tabFormat) it is the fixed position: 1 main-display, 2 prestige-button,
  3 resource-display, 4 milestones, 5 midsection, 6 clickables, 7 buyables, 8 upgrades, 9 challenges,
  10 achievements. `rbx_container` passes `i + 1`, and `rbx_layerTab` passes the position.
* `cn` + `ci` + the subtab name (`patch.tab` / the node's `tab`) identify a component stably, while path ids shift.
  Signatures claim components by this triple (§2.6).

### 1.5 New and changed nodes

  There is no time played (D§1 Q-H3).
* **End screen.** The root `col` of `rbx_endScreen()` gets `win: modInfo.winText` and
  `took: player.timePlayedReset ? null : formatTime(player.timePlayed)`. The Discord line is removed from `h`
  (D§2 #33). The Play Again / Keep Going buttons keep their `a`.

session.js:

  `activePopups[activePopups.length - 1].layer = layer` right after `doPopup(...)`.
* `rbx_popups` returns `{id, title, message, type, color, bColor, kind, layer}`:

### 1.8 Wire patch (Session → client), final shape

```
{ set = {[id] = flatNode}, del = {id…}, full = true|nil,
  tab = "none" | "options-tab" | "end" | <layer>,  tabStyle = {css},  keys = {name…},  ended = bool,
  pop = {{id,title,message,type,color,bColor,kind,layer}}?,  notice = {string}?,  export = string?,  askImport = true?,
  imp = {ok = bool, msg = string}?,          -- new: the result of the last Import (Session:import)
  save = "saving" | "saved" | nil,           -- new: one-shot save events (Worker)
  unsaved = true|nil }                       -- unchanged: this server cannot save (NOT SAVING)
```

* **Roots:** `map`, `hud`, `tab` (and `menu`, `head` until wave 3).
* **Ids are paths.** The map ids are stable because the list is fixed. The tab ids are positional.
* `plain()` drops JS `null` inside objects. So on the Luau side **absent == null**, and inside arrays null becomes
  `false`. The client treats `nil`, `false` and `JS null` as "none".

### 1.9 `Session.luau` changes

1. `view()` flattens `p.map` as `"map"`, `p.hud` as `"hud"` and `p.tab` as `"tab"` (plus `menu`/`head` until wave 3).
   Update the header comment.
2. The fallback on a failed `rbx_view` becomes
   `{map = {t="map", inside=false, c={}}, hud = {t="hud", pts="?", name="points", fr=false}, tab = {t="html", h="The page failed to draw."}}`.
3. Hard-reset arm notice (P6):
   * `_option("hardReset")` on first press sets `self.armNotice = "Press Hard Reset again within 5 seconds to wipe your progress."` instead of inserting it.
   * The reset path sets `self.armNotice = nil`.
   * `view()` moves `armNotice` into `notices` only when it is still set, `hardResetArmed ~= 0` and
     `self.JS.NOW - hardResetArmed >= 500`. The two presses can straddle a view, so the notice waits half a second.
     The client sends both presses back to back.
4. `import()` records `self.importResult = {ok = …, msg = …}` (msg = the notice text or the reason). `view()` sends
   it once as `patch.imp`.
5. `self.saveEvent` ("saving" / "saved"), set by the Worker, is sent once as `patch.save`.
6. No change to `act()`: every new action is an ordinary registered action.

### 1.10 Worker / Main.server / Store / Config

* **Worker.** `saveNow`: set `session.saveEvent = "saving"` and `pushNow = true` before `Store.save`; after a
  success set `"saved"` and `pushNow = true`. A failure leaves `unsaved` handling as is.
* **Prefs (device options, D§2 #26, D§6 Options THIS DEVICE).**
  * New RemoteEvent `Prefs` (client → server) carrying `{motion, detail, labels, size}`.
  * Main.server validates it: `motion ∈ {"SYSTEM","FULL","REDUCED"}`, `detail ∈ {"AUTO","HIGH","LOW"}`,
    `labels ∈ {"AUTO","ALWAYS","OFF"}`, `size ∈ {90, 100, 115}`; at most 1 per second.
  * It sets `player:SetAttribute("MT_Prefs", <JSON>)` at once, then saves with a 5 s debounce through
    `Store.savePrefs`.
  * On join, `Store.loadPrefs` reads the key `client_<userId>` in the same DataStore and sets the attribute before the
    first view.
  * The prefs are **never** part of the game save or the export string.
* **Store.** Add `loadPrefs(userId) -> table?` and `savePrefs(userId, table)`: plain `GetAsync`/`SetAsync` through
  the existing `retry`, with no lock (last write wins).
* **Main.server.** `ReplicatedStorage.MilestoneTreeRemotes:SetAttribute("ImportCooldown", Config.IMPORT_COOLDOWN)`,
  so the client's cooldown ring matches the server (D§7.7).
* **Ready** may now be fired again by the client (auto-resync after a render error, the OUT OF SYNC button). The
  server path already handles it.

### 1.11 Action whitelist (what the new client may send)

The server runs an action only if the last view registered it (`rbx_actions`), or if it is `{"key", name}` with
`name` in `keys`.

| action | registered by | sent from |
|---|---|---|
| `["tab", l]` | every shown map node `a` | node tap, READY gem tap, READY switcher gem, notification row, edge marker, TROPHIES (ach) |
| `["tab", "none"]` | `map.close` | panel X, Esc, tap on the strip's empty map, HOME while a panel is open, the COMPACT band close |
| `["tab", "options-tab"]` | `map.opt` | dock OPTIONS |
| `["reset", l]` | `val.ra` (map, while it can reset) and the tab's prestige-button | READY gem hold, peek HOLD TO PRESTIGE, panel CTA |
| `["chal", "mp", 21]` | `gate.a` (while `gate.show`) and mp's own challenge button | gate popover hold (portal, rift, universe tag), mp portal card |
| `["subtab", l, "mainTabs", name]` | tab buttons | panel header tabs |
| `["upg"…]`, `["buy"…]` (hold), `["click"…]` (hold when `hold`), `["grid"…]` (hold when `hold`), `["perk"…]`, `["malware"…]`, `["respec", l]`, `["sellOne"/"sellAll"…]`, `["toggle"…]`, `["chal", l, id]`, `["master", l]`, `["infobox"…]` | tab nodes | cards, signatures |
| `["opt", name]` | options tab, end screen | Options screen, modals (export, import, hard reset ×2), end screen |
| `["key", name]` | `patch.keys` | Hotkeys |

**Client rule:** an action is always the `a` table of a node **currently in the ViewStore**, fired as is. The only
action the client builds itself is `{"key", name}`. A unit lint (`port/tests/unit/lint_actions.luau`) fails if
client source contains a table literal starting with `"tab"`, `"reset"`, `"chal"`, `"opt"`, `"upg"` or `"buy"`.

### 1.12 Open / close protocol (C4, D§5.1)

* **Open layer L.** If `store.map.open == L`, show the panel and send nothing. (Re-sending `["tab", L]` resets the
  subtab to Main.) Otherwise fire the node's `a` once. The panel shell (emblem, title, hue, sub row) draws at once
  from the map node. The body shows the skeleton until a patch arrives with `patch.tab == L` (≤ 1 frame on a warm
  server). A second open request for another layer while one is pending replaces the pending one.
* **Close.** Fire `store.map.close`. The panel closes at once. A later patch confirms `map.open == nil`.
* **The server moves the tab** (a hotkey, entering the Multiverse sets `player.tab = "m"`, the end screen): the client
  follows `store.map.open`. It opens, closes or switches the panel with no fly-to, except that a universe change
  runs `frameNodes`.
* `patch.ended` shows the end screen (Overlay) on top of everything. The panel is closed underneath.

### 1.13 What the client derives (and nothing else)

Section titles (from `cn`), owned / READY counts, tier folding, the NEXT milestone (the first `ms` with `done ==
false` in ladder order), decade folds, toast coalescing and ranges, READY membership and order, plate LOD /
occlusion / collision, the frontier state (a hidden node whose Figma parent is shown in the same universe), the colour
remap, the resource → unit abbreviation table, the CTA words, the camera. **No number is ever computed on the client
except `pr / 1000`, counts, and the export string's length.**

### 2.3 Data flow

```
View.OnClientEvent(patch) ─► App.onPatch(patch)
  ├ {fatal} / {status}                  ─► overlay:screen("fatal" | "loading", text)
  ├ changes = store:apply(patch)        ─► ViewStore (pure; returns what changed per root)
  ├ changes.map ─► nodes:update(ms)  links:update(ms)  plates:update(ms)  markers:update(ms)
  │               hud:updateMap(ms)  app:syncPanel(ms.open)  app:syncUniverse(ms.inside)
  ├ changes.hud ─► hud:updateHud(store:hud())   app:setFirstRun(hud.fr)
  ├ changes.tab ─► render:apply(changes.tabPatch)  (tab.* ids only; claims re-run)  ─► panel:update(store, changes)
  ├ store.keys  ─► hotkeys:setKeys(keys)
  ├ pop / notice ─► overlay:toasts(pops, notices)
  ├ export / askImport / imp ─► overlay:modal("export" | "import", …) / overlay:importResult(imp)
  ├ save / unsaved ─► hud:setStatus(...)
  └ ended ─► overlay:screen("end", store:endScreen())

RunService.PreRender(dt): one ordered loop in App
  1 mapInput:step(dt)   gestures, inertia, rubber band, fly-to SmoothDamp  ─► camera (C, z)
  2 mapView:step(dt)    if the camera moved: 2 writes per container, tile snap, fields, biome weights;
                        then fires mapView.cameraChanged(C, z, V, m) synchronously
  3 listeners           links:onCamera (thickness if z moved > 2%), plates:onCamera (positions; LOD / occlusion when
                        z moved 2% or C moved > 8 pt), markers:onCamera, overlay:onCamera (peek scrim follows)
  4 Motion.step(dt)     Luau-driven fills (hold rings, cooldown), budgets
At rest (no input, no flight): steps 2–3 write nothing (R§9.2).
```

A render error inside `render:apply` is caught (pcall). App re-fires `Ready` once (the next patch is `full`). If it
fails again within 10 s, `overlay:screen("outOfSync")` shows OUT OF SYNC · RESYNC. `RECONNECTING…` shows when no View
event arrived for 6 s after the first screen, and clears on the next patch.

### 2.5 Render integration: skins, claims, hero

`Render.new(roots, hooks)` gains three optional hooks. The old client passes none and behaves as today.

```lua
hooks.ctx: () -> SkinCtx               -- {layer, sub (patch.tab + subtab), hue, mode, signature}
hooks.skin: (rec: Rec, n: any, ctx: SkinCtx) -> ()     -- called after _update / _updateButton, every time
hooks.claim: (id: string, n: any, ctx: SkinCtx) -> Claim?   -- called when a rec is built
-- Claim = { update: (self, store: Store) -> (), destroy: (self) -> () }
```

* **Skins** re-style in place. They are idempotent: children are get-or-create by name through `Style.child`, and every
  property a skin owns is written each call, so no stale style survives (client report §6.5). Skins choose by kind
  and `cn`: `btn:upg` → Skins/Upgrade, `btn:buy` → Buyable, `ms` → Milestone, `chal` → Challenge, `ach` →
  Achievement, `btn:grid` → GridTile, `btn:click` → Clickable, `btn:perk` → Perk, `btn:opt` → Opt, and anything else
  → Generic (quiet panel text, NOTES rows, spacers hidden). State comes from `cls` / `st8` / `done` / `gs` and the
  §1.4 fields. **Animations** (buy flash, owned transition) are keyed by `(layer, a[3])` from the node's action,
  never by the path id (client report §6.6). The first time a key is seen after a panel opens, nothing plays.
* **Claims.** When `hooks.claim` returns a Claim for an id:
  * Render builds a plain Frame placeholder at that id (same `LayoutOrder`) and does not build the subtree.
  * Every later `set`/`del` for that id or a descendant only marks the claim dirty.
  * After `apply`, each dirty claim gets `update(store)`, and reads its subtree from the ViewStore.
  * A claim is destroyed when its id is deleted or the node's kind changes.
  * Claims serve three roles:
    * the **hero** (Panel/Hero claims the first `main-display`, `prestige-button` and `resource-display` of the
      current tab at depth ≤ 3, and renders them in the pinned hero; the placeholders stay invisible);
    * the **header tabs** (the top-level `tabs` node);
    * **signature widgets** (§2.6).
* **Sections** (Panel/Sections, D§5.6). Each top-level component frame whose `cn` is in the section table gets a
  `SectionTitle` child at `LayoutOrder = -1`. If the previous visible sibling has the same `cn`, the title hides.
  `display-text` / `raw-html` become NOTES rows. `blank`, `h-line` and `v-line` are hidden. **Order** is the
  tabFormat order; the only exceptions are a signature's `order`.
* **Virtualisation** (Panel/Virtual): used by claims only (the m ladder expanded, t's upgrades, mp's buyables). It is a
  pool of `ceil(viewport / rowH) + 2` rows repositioned on `CanvasPosition`, plus a spacer Frame.
* **Budget:** ≤ 450 instances per open panel (§2.10). Cards use a fixed cell of ≤ 10 instances.

### 2.7 Input arbitration and hold safety (D§3.4)

* **One raw router** (`Input/Input.luau`) listens to `UserInputService.InputBegan/Changed/Ended` and `TouchPinch`
  (for its scale only; the midpoint comes from the two touches).
  * It tracks InputObjects by identity (a touch keeps one object for its life).
  * It exposes `Input.overUi(abs)`: true when `PlayerGui:GetGuiObjectsAtPosition` finds a visible object of HudGui,
    TopbarGui, MarkerGui, PanelGui or OverlayGui. Map art has `Active = false` / `Interactable = false`. Only node
    `Hit` buttons and the rift hotspot take input on MapGui, and those have `InputSink = None` (caps.InputSink;
    otherwise `Active = false` plus the drag flag).
* **MapInput** starts a press only if `not Input.overUi(abs)`.
  * Past 6 pt (mouse) / 12 pt (touch) the press becomes a pan, and `wasDrag()` turns true until the next press.
  * Node `Hit.Activated` checks `wasDrag()` and the 300 ms double-click debounce.
  * Wheel zoom is ignored while `overUi` (so panels can scroll).
* **Hotkeys** ignore input when `gameProcessedEvent` is true or a TextBox has focus. Order of Esc: modal > peek >
  detail sheet > panel.
* **Hold safety** (Recipes.hold, used by tray gems, peek, gate, hard reset, the buyable hold strip, Render's hold
  buttons):
  * a hold starts only after 120 ms with < 10 pt of movement;
  * it never starts during map inertia (|v| > 6 pt/s) or a pinch;
  * it cancels on > 10 pt of movement or a ScrollingFrame scroll, and then suppresses `Activated`;
  * it rewinds in 0.12 s when released early.
  * Durations: 0.6 s (tray, peek), 1.2 s (gate), 2 s (hard reset, play again).
  * Render's buyable repeat keeps its 0.25 s → 20/s behaviour, now behind the same 120 ms / 10 pt gate.
* **Hover tooltips** (mouse only) are owned by `Overlay/Tooltip`: 250 ms delay, one owner, hidden when the owner is
  destroyed (a `Destroying` hook fixes client report §6.3).

### 2.8 Motion, ReducedMotion, snapshot mode (D§8)

* `Motion.reduced()` = the Prefs.motion override, else `GuiService.ReducedMotionEnabled`, and always true in snapshot
  mode. It drives both the UI and the realm (`view:setReduced`).
* Budgets: ≤ 6 running tweens in HudGui and ≤ 40 outside the map. A keyed tween replaces its predecessor. When a
  budget is full, the tween is skipped and its end state is set directly.
* Only Position, Size, Rotation, UIScale, transparencies and UIGradient `Offset` / `Rotation` are tweened. Never
  sequences, text UIStroke Thickness or UIShadow BlurRadius.
* **Snapshot mode:** `LocalPlayer:GetAttribute("MT_Snapshot") == true`, set by the test harness before the client
  starts.
  * Reduced motion is forced, the RNG is seeded 7 and `Motion.now()` = 7.0.
  * There is no intro dolly and no flow sparks. Toast life is frozen at 60%.
  * `MT_AssumeAssets = true` makes MapView build the full tile / sprite tree with `Asset` attributes and empty
    `Image`s, so the snapshot renderer can draw the PNGs (§5.5).

### 2.9 Layout and coordinates

* **Breakpoints and s:** D§10 verbatim (`Layout.mode`, `Layout.s`), recomputed on `ViewportSize` and Prefs.size
  changes. s never goes below .90 on desktops or 1.0 on COMPACT, whatever Interface Size says. A
  `GuiService.PreferredTextSize` change fires `Layout.changed` (text frames re-measure) but does not change s: the
  engine scales the text (D§9.5).
* **Abs space:** the space of `GuiObject.AbsolutePosition`. Every Rect in the client is in abs space.
  * `Layout.duToAbs` converts D coordinates (screen du from the device top-left) with the gui root's
    `AbsolutePosition` and s.
  * `Layout.inputToAbs` converts `InputObject.Position` into abs space. It is the only such conversion. Its offset
    is verified in Studio (§8 item 5) and the mock follows the tooling report's convention (Position excludes the
    inset).
* **MapGui** has no UIScale. Its Box sits on whole px. V = Box / m (R§2.6).
* The HUD registers its rects (capsule, pill, dock, tray, portal, visible toasts, and `Layout.topbar()` for the
  Roblox buttons) with `Layout.setRect`. Plates and markers read `Layout.rects()`.
* **Strip:** while a side sheet is open, `Panel:geometry().sx` (abs px of the backdrop's left edge) is handed to
  `MapView:setRect` and `Layout.setSheet`. When the strip is under 460 du the sheet is full screen, and App sets
  `MapGui.Enabled = false` and `view:setAmbient(false)` after the slide (D§3.6).

### 2.10 Performance rules (D§17 gates)

* MapGui per moving frame: 2 writes × 10 containers (8 layers + Links + Nodes), tile snapping (≤ 72 HIGH), 21 plate
  positions, and the field updater. **0 writes at rest.** No layout objects in moving containers. Node conditional
  parts are created lazily.
* Plate text is written at ≤ 5 Hz and only when it changed. HUD numbers are written only when their string changed.
* HudGui / TopbarGui: ≤ 80 instances and ≤ 6 running tweens. PanelGui: ≤ 450 instances for the open panel.
* `unit` tests count writes through a mock property-set hook (§5.3) and fail above these numbers.

## 3. Asset pipeline

### 3.1 What exists and stays (art/README.md, R§3)

```sh
cd $REPO/art && export NODE_PATH=$(npm root -g)
node camera.js --test            # contract: coverage, depth order, tiles, budget, sprites, fields, biome
node render.js all               # painters -> out/<layer>.png (HIGH texture) + previews; sprites -> out/sprites.png/.json

node roblox/upload.js --dry-run  # -> src/shared/Assets.luau with nil ids
```

* The tiler already produces HIGH (the render, forced opaque where the layer is opaque) and LOW (premultiplied 2×2
  box, 2×2 HIGH tiles merged, half-width last column or row when odd).
* Tile rects come exactly from `camera.js tileRects`. Every image is ≤ 1024².
* Alpha bleed is a push-pull pyramid in premultiplied space. PNG encoding is deterministic (sha256 stable).
* The uploader is done:
  * `POST /assets/v1/assets` multipart with `assetType: "Image"`, then polls `GET /operations/<id>`;
  * one rate limiter (`--rpm` 50);
  * exponential backoff with jitter that honours `Retry-After` / `x-ratelimit-reset` on polls;
  * create retries only when Roblox cannot have processed the request (429, 503 + Retry-After, pre-connect errors);
  * "unconfirmed" bookkeeping with `--adopt` and `--retry-unconfirmed`;
  * `uploaded.json` (sha256 → id) for resume and dedupe.
* Auth: `ROBLOX_API_KEY` (sent as `x-api-key` when set; the proxy injects one for apis.roblox.com otherwise) and
  `ROBLOX_CREATOR=user:<id>|group:<id>`.
* PNGs are not committed (`.gitignore`). Anyone running the pipeline re-renders first (`render.js all`).

  * HIGH = `ui_atlas.png` as is;
  * LOW = the 512² premultiplied 2× downsample, with region rects halved (odd sizes rounded to even in the spec);
