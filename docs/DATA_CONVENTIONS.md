# Reference-data conventions (src/shared/Data)

Single source of truth for the decisions the generated modules encode.
Modules are generated by `tools/gen_luau_data.py` from `research/vs/*.json`.
Regenerate; never hand-edit.

## Scale convention (decided once, applied everywhere)

`DISPLAY_SCALE = 10`, and the **DISPLAY** side is canonical.

Vampire Survivors' shipped data stores damage and health on a uniform internal
÷10 scale. Both weapon damage and enemy health are therefore carried on the
display side of that factor:

| field | module | value | shipped raw |
|---|---|---|---|
| `knife.baseDamage` | `Weapons.luau` | `6.5` | `rawPower = 0.65` |
| `zombie.health` | `EnemiesWaves.luau` | `10` | `rawHealth = 1` |

The untouched shipped numbers are kept alongside as `rawPower` / `rawHealth`, so
nothing is lost and no consumer has to guess which side a number is on.

## Other conventions

* All in-run times are **seconds**, as plain numbers (`10:00` -> `600`).
* Canonical stat keys from `research/vs/SCHEMA.md` are used verbatim.
* `null` in the source becomes the sentinel `Module.UNKNOWN` -- never `0`,
  never `false`, never an invented number.
* The shipped per-enemy knockback field is knockback **taken** (higher = knocked
  further, `0` = immune), so it is named `knockbackTaken`, not
  the misleading resistance-style name used in `SCHEMA.md`.
* `unknowns`, `conflicts` and per-record `sourceIds` are carried through intact.

## Status

Reference points for deriving our own balance. **Not** values to ship verbatim,
and not game-facing content.
